五个阶段，同一种野心

表面是功能密度极高的发版节奏，底层是连续把「人必须盯着的步骤」外包给系统：先会规划与验证，再能编排与并行，然后出现在协作入口，最后把代码、环境和机群收进自己的平台。

2025.09 – 2025.10

从编辑器到 Agent IDE

用 Plan Mode、内置浏览器与 Composer 把「写代码的工具」改写成「能规划、能验证、能并行干活」的工作台，完成品类心智切换。

2025.11 – 2026.02

把 Agent 做成可编排系统

评审、调试、Skills、Subagents、插件市场依次落地，让能力从单次对话变成可复用的组织资产。

2026.03 – 2026.04

Agent 成为一等公民

Composer 2 压低多智能体成本，Cursor 3.0 用 Agents Window 把 IDE 翻转为 Agent 运行时。

2026.05 – 2026.07

工作流外溢到协作入口

PR、Slack、Jira、Teams、iOS、自动化触发器把产品铺到开发者已经在的地方，降低获客与日常触达成本。

2026.08 – 2026.09

从工具到软件工厂

Origin 托管代码、Builds 预热环境、Subscriptions/Goal 持续干活、自托管机群与无仓库起步，把编辑器做成端到端交付平台。

四维解读：这些更新在增长上到底做了什么

功能、交互、性能、生态不是四份独立路线图，而是同一漏斗的不同杠杆：功能制造理由，交互保护习惯，性能决定敢不敢默认打开，生态决定走不走得掉。

新品类需要新动词

功能创新 → 用户获取

  • 2.0 的 Multi-Agents 与 Composer、3.0 的 Agents Window，是在重新定义品类：不是「带 AI 的 VS Code」，而是 Agent 运行时。获客话术从补全准确率，换成「一支会干活的小队」。
  • Plan、Debug、/multitask、/goal、Subscriptions 构成能力阶梯：先让新手完成中等任务，再让专家把人从循环里拿出来。每个台阶都是一层可对外讲的故事。
  • /best-of-n 与并行 Build 是天生可演示功能，适合销售现场和社交传播：同一需求多结果对比，比基准测试图表更可信。

减少自我打断

交互优化 → 用户留存

  • 澄清问题、旁路侧聊、不砍断的转向，都在降低「Agent 很强但我会用砸」的挫败。留存的对手是认知过载，不是竞品功能清单。
  • 平铺布局、Inbox、移动审 PR，让并行从能力变成可管理的界面。功能若无法被注视，就不会被形成习惯。
  • 2.3 假期稳定性专项说明：主动少发功能、修聊天丢失和更新骚扰，本身就是留存战役。信任一旦裂开，模型再强也回不来。

延迟是定价，也是习惯

性能改进 → 体验与转化

  • Grep、LSP、首 token、环境启动、评审时长，决定用户敢不敢把「每次保存/每次 PR」交给产品。慢的智能会被跳过，快的智能会成为默认路径。
  • Builds 把安装依赖从会话临界路径拿掉，转化的是「再开一个 Agent 试试」的边际意愿。
  • Router 把性能问题翻译成套餐问题：同一产品里用模式选择智能/成本，减少因账单惊吓导致的降级或流失。

长在别人的操作系统上，再长出自己的

生态整合 → 粘性与场景扩展

  • 先做 GitHub/GitLab/Slack/Jira 的好公民，再推出 Origin——这是经典的平台策略：借场景获客，用系统留人。
  • MCP + 插件 + Skills 让 Cursor 成为集成总线。谁的总线接了 Figma、Stripe、Gmail，谁就占据日常时长。
  • 自托管与「跑在你已有的沙箱上」打开受监管与平台工程场景，把拒绝理由从「数据不能出域」改写成「执行留在我这边」。

增长启发点

每一条都拆成：Cursor 实际做了什么、增长上应如何读、建议盯的指标。指标是观察建议，不是官方披露。

用户获取

用户获取
把产品铺到用户已经在的地方，而不是再发明一个入口

产品动作。 Slack（含表情触发与跨频道）、Jira 指派、Microsoft Teams @提及、GitHub 事件、iOS/iPad Inbox，同一套云 Agent 从协作软件里被叫醒。

增长读法。 开发者的「开始工作」往往发生在工单和消息，而不是 IDE。入口外溢把获客从下载安装，变成「同事 @ 了一下」。病毒系数来自工作流，而不是分享按钮。

跟踪：非 IDE 发起的 Agent 会话占比、首次付费前是否出现过 Slack/Jira 触达、被 @ 的未安装用户转化。

用户获取
先给「wow」，再谈仓库权限

产品动作。 2026-08-27 起 Cloud Agents 不再强制绑定 GitHub：Start from scratch → 预览 → 再创建 Origin 仓 → 可选 Vercel 发布。印度 Start 套餐用本地价与 UPI 降低支付摩擦。

增长读法。 传统开发者工具把 OAuth 仓库授权放在激活之前，这是最大掉队点。先交付可感知产出（页面、PR、URL），授权变成「保存工作」而非「才能开始」。新兴市场用购买力定价，而不是全球统一 ARPU。

跟踪：无仓会话 → 创建仓库转化、未完成 GitHub 连接的激活率、Start 套餐相对全球 Pro 的试用到付费率。

用户获取
自研模型既是产品差异，也是获客广告

产品动作。 Composer 1→2→2.5 持续用速度与长任务能力做发布事件；Grok 4.5 进入桌面/Web/iOS/CLI/SDK；/best-of-n 让对比结果可演示。

增长读法。 模型发布是稀缺的媒体事件。把「更快/更便宜/更能熬」做成可感知的产品时刻（4× 速度、首周双倍用量），比功能列表更能拉动安装。多模型并存避免押注单一供应商叙事。

跟踪：发版周新安与回访、默认模型切换率、best-of-n 使用与分享截图外溢。

激活转化

激活转化
激活定义从「打开编辑器」改成「完成一次可验证交付」

产品动作。 Plan Mode → 浏览器验证 → Design Mode → 并行 Build → 拆 PR → Bugbot /review → 预览端口转发。

增长读法。 Aha 时刻应绑定「我看见它跑起来了 / 我开出了 PR」，而不是「我跟 AI 聊了一句」。验证闭环越短，付费理由越硬：省的是联调与等待，不是键入。

跟踪：D1 内完成「计划+落地+预览或 PR」的比率；仅聊天未改文件的用户 7 日流失。

激活转化
用默认安全换「敢点运行」

产品动作。 沙箱终端 GA、网络域名白名单、Auto-review 运行模式、密钥与 Agent 运行隔离、企业强制策略。

增长读法。 Agent 产品的激活杀手是恐惧：误删、泄密、乱打生产。安全默认不是合规附录，而是让用户按下 Run 的转化组件。审批从「每条命令」升级到「分类器+沙箱」后，速度与安全感可以同时要。

跟踪：首次 auto-run 开启率、因权限提示放弃的会话、企业 POC 中安全问卷周期。

留存复用

留存复用
留存来自「任务可以在人不在时继续」

产品动作。 Cloud Agents、/loop、Subscriptions、/goal、iOS Remote Control、Live Activities、合上笔记本仍可跑。

增长读法。 日活不再等于「坐在 IDE 前」。异步完成把产品嵌入睡眠与会议间隙，形成习惯回路：走之前丢一个目标，回来收结果。移动端不是缩小版 IDE，是 Agent 的通知与舵。

跟踪：云会话跨 4 小时仍完成的比例、移动端仅审查/合并的 DAU、订阅类自动化周活跃。

留存复用
交互优化的本质是保护「主线程心流」

产品动作。 Side chats、/btw、不打断的 steering、对话搜索、平铺布局、紧凑回复、Quick-action pills、计划澄清 UI。

增长读法。 Agent 越能干，越容易把用户拖进旁支。产品用「旁路对话 + 事后回灌」保护主任务，用搜索对抗长 transcript 失忆。留存提升来自更少的自我打断，而不是更多按钮。

跟踪：主会话完成率、side chat 回灌主线程次数、长会话中途弃用率。

付费与扩容

付费与扩容
性能改进直接改写单位经济，从而改写套餐设计

产品动作。 Instant Grep、LSP/内存、Hooks 40×、Bugbot 3× 更快且更便宜、Builds 启动 10× / 首 token 3×、Composer 低价、Router 按任务分流。

增长读法。 在用量计费世界，延迟和 token 就是 COGS。降本让「默认开并行、默认跑评审、默认预热环境」成为可能，用户感知是「突然什么都能天天用」。定价从请求次数走向智能路由 + 用量池，企业要的是可预测，个人要的是不心疼。

跟踪：同任务 token 成本、因额度耗尽停用的比例、Router Cost 档与 Intelligence 档的满意度差。

付费与扩容
席位费让位给「工作发生额」，用组织层级卖扩容

产品动作。 Bugbot 取消席位费；用量池拆分；软消费上限；Org > Teams > Groups；模型/市场按组管控；印度本地套餐。

增长读法。 工具席位在 CFO 那里是成本项，工作流用量是「和产出相关的基础设施」。去掉评审席位门槛换渗透，再用重度用量收回。组织对象从团队管理员升级到 IT/采购，才卖得出集团合同。

跟踪：团队内激活席位比、用量集中度（头部 20% 用户贡献）、组织创建后 90 天净扩容。

粘性与扩展

粘性与扩展
生态不是插件数量，是「组织知识可安装」

产品动作。 Marketplace、Team MCP 一次配置处处运行、SKILL.md、插件 Canvas、GitLab/Bitbucket/Azure 导入插件仓、Google Workspace 插件。

增长读法。 粘性来自切换成本：团队规则、允许的 MCP、沉淀的 skills、挂钩子的合规。市场排行榜提供内部社会证明。谁成为团队默认环境，谁就赢了下一批新人。

跟踪：每团队已安装插件/技能数、跨 IDE/CLI/云复用同一 MCP 的比例、卸载编辑器后仍跑的自动化数。

粘性与扩展
向平台延伸：代码托管 + 自有基础设施 = 工作系统锁

产品动作。 Origin 仓与 PR、GitHub 镜像、Vercel/Depot/Buildkite、自托管池、第三方沙箱、无仓到有仓的同一条故事线。

增长读法。 编辑器可被替换，承载仓库、PR、CI 预览和机群的系统很难被替换。这是从「AI 功能」到「软件工厂」的跳跃：扩展场景包括内部平台、外包交付、黑客马拉松冷启动、受监管行业的数据不出域。

跟踪：Origin 为源的仓库占比、自托管任务占比、多应用扩展同时开启的组织留存。

可借鉴的产品策略

不要复制「再做一个 Agent IDE」。要复制的是决策结构：入口放在哪、权限何时要、默认开什么、如何用成本曲线改行为、如何从插件变成系统。

按产品类型的落地矩阵

ToC 工具 / 创作者产品

  • 无账号或无仓库的 60 秒出活
  • 移动端只做委托与验收，不做完整创作桌面缩小版
  • 把「夜间生成」做成订阅理由

开发者平台 / DevTools

  • PR 与工单里的最小 Agent 动作
  • 预构建环境换秒开，用启动时延当转化杠杆
  • 技能市场 + 团队分发形成组织默认

中后台 SaaS

  • 表情/评论触发的自动化，而不是新的工作台
  • 风险分级自动运行，降低「机器人不敢开」
  • 先双向同步再谈替换客户源系统

企业 AI 落地

  • 执行留在客户机群或现有沙箱
  • Org 层级、审计、模型墙作为销售包，而不是售后补丁
  • 用自研或路由模型讲清楚单位智能成本
